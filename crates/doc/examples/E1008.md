---
title: Access outside the library
---
A library uses its own declarations and the standard library's, and nothing else: not another library, not the program that lists it, not a global.

Every library a program lists is read into one program with it, and the program's code sees them all. A library's code does not: what it names means the same in every program, whatever else that program lists or declares, and a namespace the program writes, even under the library's name, is none of the library's.

A block of the library takes what it needs through its inputs and in-outs, and a variable it declares `AT %I*`, `%Q*` or `%M*` is located by the program's `VAR_CONFIG`. A `VAR_EXTERNAL` in a library has no global to name.

The error is reported when a program builds with the library, and in the library's own folder, whose `config.toml` says `type = "library"`.
