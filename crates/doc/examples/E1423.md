---
title: Part of a wider address
---
An address inside a wider one the program also names is part of it. Each size counts in its own units and the image is little-endian, so beside a `%QW0`, `%QX0.3` is its bit 3 and `%QB1` its high byte. A part is stored in the wider address's cell and has no storage of its own.

Reading a part, assigning it, and binding a function block's output to it all work. The uses that need storage of its own do not:

- passing it to a `VAR_IN_OUT`, or taking `REF()` of it, which both need its address;
- binding a function's output to it, which the function writes through an address;
- counting a `FOR` loop with it;
- declaring it `RETAIN`, which belongs on the variable located at the wider address;
- declaring it with a type that does not hold its bits as they are, such as `SINT` or `REAL`. A part reads as a bit string, so only `BOOL`, a bit string or an unsigned integer of its width will do.

```iecst
FUNCTION_BLOCK Flip
VAR_IN_OUT v : BOOL; END_VAR
    v := NOT v;
END_FUNCTION_BLOCK

PROGRAM P
VAR f : Flip; w : WORD; END_VAR
    w := %QW0;
    f(v := %QX0.3);
END_PROGRAM
```
