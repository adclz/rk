---
title: Not representable on an import
---
An `{extern}` FUNCTION is a WASM import: its VAR_INPUT are the params, and its VAR_OUTPUT and its return value, last, the fields of the record it returns. An `{extern async}` FUNCTION_BLOCK is one too: its VAR_INPUT are the params, and its VAR_OUTPUT but DONE the fields of the result.

It cannot have a VAR_IN_OUT, a STRUCT, ARRAY, instance, `ARRAY[*]` or variadic input, an aggregate or STRING output or return value, or a body. An `{extern async}` FUNCTION_BLOCK has no METHOD, EXTENDS or IMPLEMENTS either: the block is its call, and the host has no other code of it.

An import from a plain module, like `'modbus'`, is typed in WIT from its declaration. It takes scalars and STRINGs, 16 values at most with a STRING counting two. So it cannot have a `REF_TO` input either.

An import from an interface of a package, like `'wasi:clocks/monotonic-clock@0.3.0'`, keeps the types the package's WIT gives it, in their core form: a record comes back in VAR_OUTPUT, one for each of its fields, or through a `REF_TO` input. A STRUCT or an ARRAY input would go as an address into rk's own layout, which no function of a WIT reads.

A FUNCTION imported from a package's interface takes one block the host writes: a string, into its first STRING VAR_IN_OUT; a list, into its `ARRAY[*]` VAR_IN_OUTs of scalars or STRINGs; or a text, an error's or a case's, into its first STRING VAR_OUTPUT, cut to fit. A second one, or one beside another, has nowhere to go.

```iecst
{extern 'host' 'fill'}
FUNCTION fill : INT
VAR_IN_OUT buf : INT; END_VAR
END_FUNCTION
```
