---
title: Loop that never ends
lint_rule: endless-loop
---
A WHILE or REPEAT loop changes nothing its condition reads, and has no EXIT, RETURN or `__RAISE` to leave by.
Once it starts, it never ends, and the scan never finishes.

An input does not change during a scan, so waiting for one in a loop is the usual case: the next value arrives with the next scan, which the loop keeps from starting.
Test the input once per scan instead, with an IF.

A call in the loop may change a member, a global or an in-out, so the rule counts only what a call cannot reach: the loop's own writes, and the local variables of a FUNCTION or METHOD.

```iecst
FUNCTION_BLOCK Door
VAR_INPUT
    closed : BOOL;
END_VAR
    WHILE NOT closed DO
    END_WHILE;
END_FUNCTION_BLOCK
```
