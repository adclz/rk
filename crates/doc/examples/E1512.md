---
title: Import name not a WIT name
---
An `{extern}` FUNCTION is imported under the names it gives, written as WIT writes them. rk converts nothing, so the host defines the names the declaration gives.

The module is a WIT name, like `modbus`, or an interface, like `acme:modbus/rtu@1.0.0`, with one namespace and one interface: the component model's tools take no nested name yet. The function's name is a WIT name: words of lowercase letters and digits joined by `-`. A WASI import may also be a resource's function, named as WIT names it, `[constructor]R`, `[method]R.f` or `[static]R.f`, or the drop of a resource's handle, `[resource-drop]R`; and a stream's or a future's built-in, named after the function whose type has the stream, like `[stream-new-0]write-via-stream`. Only WASI's interfaces have resources: a host module's WIT is written from its declarations, which make none.

For a module other than WASI's, each `VAR_INPUT` and `VAR_OUTPUT` is named in WIT by its name in lowercase, each `_` written `-`: `start_address` is `start-address`. A name that leaves a word empty, like `x_`, or that has a letter outside ASCII, has no WIT name. The component model compares names without their `-`, so `ab` and `a_b` are one name to it.

The `VAR_OUTPUT` are the fields of the record the import returns, and the return value is its last, named as the import is: no `VAR_OUTPUT` can take that name.

```iecst
{extern 'modbus' 'read_coils'}
FUNCTION ReadCoils : UDINT
VAR_INPUT start_address : UINT; count : UINT; END_VAR
END_FUNCTION
```
